# 04 · 开发计划与工作量

> 估算口径：**1 人日 = 6 有效小时**（不含会议/环境折腾）。区间给 P50（现实）与 P80（含返工）。
> 假设：开发者熟悉 TypeScript/React，不要求 Rust 经验；有 AI 编程助手可用。

## 4. 建议的执行顺序（先拆最大的不确定性）

1. **第 1 周**：先做 M0.5 + M1.1 —— 用探针把六个来源的真实结构全部摸一遍（含让用户导出一份 DeepSeek 数据）。这一步决定后面 90% 的设计是否成立。
2. **第 2–3 周**：`openai-web` + `codex-local`（一「云」一「端」各打通一个），跑通完整流水线到 SQLite。
3. **第 4 周**：极简 UI（列表 + 详情 + 主干渲染），拿到可演示版本 → 此时可以判断产品是否成立。
4. **第 5–6 周**：补齐其余四个适配器。
5. **第 7–9 周**：M4 查重校验 + M5 搜索（这是差异化，必须留足时间）。
6. **第 10–12 周**：M3 打磨 + M6 打包。

## 5. 路线图（v1 之后）

| 版本 | 主题 | 内容 |
|---|---|---|
| v1.1 | **记忆** | 从 `about_user_message` / `memories.json` / 高频主题抽取「关于我的事实」，带 `provenance(item_id)`、跨会话去重、可编辑可删除；导出为 `AGENTS.md` / `CLAUDE.md` / MCP 资源 |

| v2.0 | **统一工作记忆** | 语义检索（sqlite-vec + 本地 embedding）、项目档案（按 cwd/repo 聚合）、跨来源「同一项目」串联、只读局域网多端查看 |

**为什么把记忆放后面**：记忆的质量上限由「会话库是否完整、去重是否干净」决定。先有可信档案，再谈从中提炼。反过来做，得到的是一个自信地记错事的助手。

## 6. 已敲定的边界决策

1. **目标平台与产品形态**：**核心 CLI 优先，搭配简短轻量的桌面 UI，v1 仅限 Windows 端**（macOS 后续视需求再议）。
2. **桌面 UI 技术栈**：弃用 Electron 与 WebView2，直接采用 **Flutter (Dart) 构建 Windows 原生桌面端（`flutter build windows`）**，与兄弟项目 `Chatea` 共用同一套桌面外壳风格、OCA Dart 模型与消息/分支树渲染组件。
3. **OCA 中间表示标准包**：在 `SessionManager/packages/oca` 内孵化（CC0 规范 + MIT SDK），生成 Go/Dart/TS 类型供 `SessionManager` 桌面端与 `Chatea` 直接消费；`sm export --format oca` 产出的归档可直接导入 `Chatea` 续聊。
4. **是否要加密库**：v1 暂不引入 SQLCipher 原生编译复杂度，建议用户将库置于加密盘或 BitLocker 卷。
5. **预期数据规模**：按 10 万条 item / 20 GB 媒体做大负载外置（>32KB 进 `blobs/`）与流式解析预算。
