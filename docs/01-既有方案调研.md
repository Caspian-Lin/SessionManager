# 01 · 既有方案调研

> 调研时间：2026-11。Star 数为调研时快照，仅用于判断活跃度与生态位，不代表质量。
> 方法：GitHub 仓库搜索（`chatgpt export viewer` / `claude export viewer` / `ai conversation archive` / `deepseek export` 等 10+ 组关键词）+ 阅读 README/源码树 + 各官方帮助文档核对。

## 1. 结论先行

**市场是「碎片化的单点工具」，不是「已被解决的产品」。**

- **多**：单 provider 的导出包查看器（几十个，多为几百行 HTML/Python）。
- **少**：跨 provider 的统一归档（个位数，且普遍只做「捕获 + 浏览」）。
- **几乎没有**：① 多次导出之间的**会话去重与差异校验**；② 网页对话与**本地 Agent 轨迹**（Codex / Claude Code）用统一行为接口并列归档与检索；③ **分支保真**（regenerate 出来的旁支默认被丢弃）；④ 大负载（内联 base64、MB 级工具输出）的工程化处理。

也就是说：需求侧「归档 + 检索 + 迁移到记忆」已有验证（kept 上了 Product Hunt，VESTI 拿了黑客松金奖），但**「重复导出后如何确定这份数据是新的、完整的、没重复的」这个刚需没人做**——这恰好是用户的第 3 条需求。

分类看：
- **① 导出包查看器**（大多数）：无持久库，一次性渲染。价值在「格式知识 + 渲染细节」。
- **② 本地 Agent 工具**（dsh-chat-import、codex-history-viewer、claude-code-log 类）：格式知识极强，但目标是「续聊/迁移」。
- **③ 记忆中枢**（kept、VESTI、ThreadShelf、resonant-archive）：走扩展抓取 + 向量检索，重「回忆」，轻「档案完整性」。
- **④ 商业产品**（Msty / Saner / Mem 等）：云端为主，本地数据主权与导出包归档不是卖点。

## 3. 可直接借鉴的具体机制

不是「抄功能」，是抄这些已经踩过坑的实现决策：

1. **localhost 收数据 + 扩展负责抓**（kept 的 `127.0.0.1:18241`、gpt-exporter 的内嵌 server）：把「采集」和「存储」解耦，扩展只发规范化 payload。→ 本项目把它作为**未来的云会话自动导入**通道，v1 不做。
2. **内容哈希导入台账**（Codex 的 `external_agent_session_imports.json`）：`source_path + content_sha256 → imported_id`，天然幂等。→ 直接升级为我们的 `import_batch` / `import_file` 双层哈希。
3. **分片与伪装扩展名的容错**（Gusarovv 那个 viewer 处理 `conversations-000.json` 与 `.dat`）：导出包**不能假设文件名**，必须按内容嗅探。→ 适配器一律「先探针、后解析」。
4. **树视图而非列表**（chatgpt-json-tree-viewer）：`mapping` 是图，按 `current_node` 回溯只是「主干」，旁支也是用户资产。→ 原生会话在投影为展示树时，`parent_id` 与激活分支标记必须是一等公民。
5. **解析 `content[]` 而不是 `text`**（Empirica 的 [CLAUDE_AI_PARSER.md](https://github.com/EmpiricaAI/empirica/blob/main/docs/reference/api/CLAUDE_AI_PARSER.md) 实测 654 条里 87 条两者不一致，13%）：Claude 导出的 `text` 是丢了 tool 块的降级视图。
6. **Markdown vault 作为逃生舱**（kept）：即使数据库损坏，用户仍有可读文件。→ 本项目提供「导出为 Markdown/JSONL」的能力，并按原生单会话切片落盘，避免跨格式重编码带来的信息损毁。
7. **30+ 本地格式清单**（dsh-chat-import 的 `SOURCES`）：省掉大量格式调研。可直接作为 v2 适配器 backlog（gemini / cursor / opencode / kimi / qwen / cline / goose / zed …）。
8. **多态直读而非重造通用持久化规范**（参考 `cc-switch` 等工具的本地会话读取模式）：不同 provider 的会话天然存在异构字段，且查重与增量演化校验主要发生在**同一 provider 内部**；无需强制先把所有数据重写为另一种标准 JSON（如 OCA）再存盘，只需按源类型抽象为强类型对象并实现统一的行为接口（校验、语义摘要/哈希、检索切片、按需 UI 投影）。

## 4. 合规与边界

- **只用官方导出 + 本地文件**：不做登录态抓取、不逆向私有 API。这是与 kept/VESTI 类项目最大的产品差异，也避开了 ToS 风险。
- **原始层只读**：导出包解压后按 sha256 落盘，永不被程序改写；所有转换产物可重建。用户要求「原始数据留存不动」在此落地为数据结构约束，不是口号。
- **不内置云同步**：默认零出网；「记忆/语义检索」若需模型调用，走用户自填的 API key 或纯本地模型，且必须显式开启。
- **许可证**：上述借鉴点均为机制/思想；若复制代码需逐一核对（kept=MIT、claude-archive 未见 license 文件、dsh-chat-import=MIT）。

## 5. 定位结论

> **不是又一个「导出包查看器」，而是「会话存档系统」**——有账本（批次/哈希/校验）、有主键（provider 原生 id + 内容指纹）、有版本（修订历史）、有媒体库（内容寻址），然后才在上面长阅读器与记忆功能。

- 对个人：*注销账号前，把 5 年 ChatGPT/Claude/DeepSeek 对话变成一份可检索、去重过、能自证完整的本地档案。*
- 对重度 Agent 用户：*把 Codex / Claude Code / DSH 的会话日志变成可读、可引用、可跨工具统一检索的工作记忆。*
